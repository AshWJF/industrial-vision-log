## 三组必设参数
| 参数 | 值 | 作用 |
|---|---|---|
| depth_module.visual_preset | 3 (High Accuracy) | 深度高精度模式 |
| rgb_camera.enable_auto_exposure | False | 关自动曝光，固定亮度 |
| align_depth.enable | true | 深度图对齐到彩色图 |

注：`align_depth.enable` 是 **launch 级参数**（`rs_launch.py align_depth.enable:=true`），和另两个运行时参数不是同一层：它在启动时决定要不要创建 `aligned_depth_to_color` 发布器，运行时 `ros2 param set` 通常要 re-enable 或重启才生效，所以不用单独 set，但**每次启动命令里都得带上**。参数名经官方 issue #2727 确认（不是 `align_depth:=true`）。

**对齐已验证生效**（22:49 补）：下午 15:10 的启动命令就带了这个参数；更直接的证据是 `w2_measure.py` 订阅 `/camera/camera/aligned_depth_to_color/image_raw` 并成功取到 Z —— 这个话题**只有对齐开启才会发布**，脚本收不到就只会打印 `[FAIL] 10 秒内没收到深度图`。所以功能上没有缺口，缺的只是把三条 `ros2 param get` 回读截图入档。

## 测量对象与角色（2026-11-17 用户澄清）

| 物体 | 本轮里的真实角色 | 说明 |
|---|---|---|
| **亚克力板 300×300mm**（网购标准板） | ① 的被测方块；**② 里当尺子用**：把板子卡在相机与被测物两端，用已知 300mm 边长量出距离 | 一件东西两个用法，说「亚克力板那轮」时要讲清是 ① 还是 ② |
| **牛奶盒** | ② 的被测物，**只测距离** | 中途沟通里名称被豆包叫混过，**文档最终定义正确：② = 牛奶盒** |
| **铝制电机支架** | ③ 的反光件，**只测了反光 / 深度缺失率** | 中途名称被叫混过，**文档最终定义正确：③ = 支架** |

**一句话规则**：一个被测物 = 一组数据 = 一个距离；不同物体、不同距离的数字不能放在一起比误差。
① 在约 75cm、② 在约 30cm，本来就是两轮；豆包一直拿「牛奶盒的距离」去比「之前测亚克力板的距离」，才造成「+0.16% vs +2% 差 12 倍」的假象。**不是数据不自洽，是对比对象错了。**

## 三组精度实测

### ① RGB 测边长
| 项目 | 数值 |
|---|---|
| 被测物 | 300×300mm 亚克力板 |
| 距离 | 约 75cm（脚本从深度图四角读取 Z = 750.5mm） |
| 脚本算出物理边长 | 300.47 mm |
| 真实边长 | 300.00 mm |
| 误差 | +0.47 mm（+0.16%） |

- Z 的来源：`w2_measure.py square` 在**彩色图**上点 4 个角，再拿**同一组 (x,y)** 去 `/camera/camera/aligned_depth_to_color/image_raw` 取四角 7×7 邻域的深度中值，本轮读出 750.5mm。能这么做的前提就是深度已对齐到彩色视角；若没对齐，同一个 (x,y) 在深度图上指的是另一处空间点（RGB 与深度有基线差、FOV 也不同）。
- 交叉验证：`300 × fx / 750.5 ≈ 364px`，与脚本量到的像素边长一致，这一轮内部自洽。
- ⚠️ 300.00mm 是**网购标称值**，不是卡尺实测。主体文件 W2 要求「RGB 测**卡尺量过的方块**边长」，基准仍需补一次实测（卡尺，或用 A4 纸 297×210 复核）。

### ② 深度测距离
| 项目 | 数值 |
|---|---|
| 被测物 | 牛奶盒（只测距离） |
| 深度中值（5帧中位数） | 306.0 mm |
| 实际距离 | 300 mm —— 用 300×300mm 标准亚克力板**卡在相机与牛奶盒两端**量出 |
| 误差 | +6 mm（+2%） |

- **距离基准是实测的**：没有卷尺，改用网购标准 300mm 亚克力板当尺子，两端分别顶住相机与被测物，所以「约 300mm」有依据，**这组数字有效**。
- 与 ① 的 750.5mm、③ 的 778.0mm 不是同一轮、也不是同一距离，**不矛盾**，不要互相比较。
- +6mm 里包含「板子顶的是相机外壳 / 深度值从光学基准算起」这类基准面差异，属正常量级。
- 记录改进：以后写「距离基准用什么量的、卡在哪两端」，别只写「约 300mm」。

### ③ 反光金属件深度缺失率
| 项目 | 数值 |
|---|---|
| 被测物 | 铝制电机支架（只测了反光） |
| 距离 | 约 78cm |
| 平均缺失率 | 3.0% |
| 边缘/孔位缺失率 | 6%~9% |

- 名称中途叫混过，但**最终定义无误**：② 牛奶盒、③ 支架。
- 5 帧缺失率为 `0.0 / 0.1 / 6.2 / 0.0 / 8.8 %`，波动很大，说明金属件没稳定停在中心 ROI；平均值代表性不足，固定后重测。
- ⚠️ **与主体文件的差距**：W2 第③组原文「反光金属件**重复①②**，记深度缺失率」，本轮只跑了 `depth`（缺失率），**没有跑 `square`**，缺金属件上的 RGB 边长与误差对比。补不补由用户拍板，正文不改。
- ROI 口径（脚本实际用的）：画面中心 80×80、`depth==0` 记为无效、连续 5 帧。
