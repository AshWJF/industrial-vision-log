# 2026-11-18 学习日志（W2 验收补漏）

> 阶段：S0 启动期，W1 时间窗（11.13–11.22）内，提前推进 W2「图像进 ROS + D435i 上手」的收尾。
> 全天在 Ubuntu 22.04 + ROS2 Humble 上，用 D435i 把 W2 三组精度数字做实、补内参、清掉 image_transport 欠账，并写文档。

## 一、今天做了什么

1. **重启相机 + 三组参数**：`ros2 launch realsense2_camera rs_launch.py align_depth.enable:=true`，再 `ros2 param set` 设 `visual_preset=3`、`enable_auto_exposure=False`，回读确认，`topic list | grep aligned_depth` 验证对齐话题存在。
2. **① RGB 测边长**：用 100×100mm 茶色亚克力板（贴白墙）跑 `w2_measure.py square 100`，得 **100.13mm，+0.13%**。
3. **② 深度测距离**：白墙 300mm→读数 311.0mm（+11mm）；铝支架正面 286.2mm→读数 296.0mm（+9.8mm）。
4. **③ 反光金属件**：缺失率 4 档（0% / 7% / 3% / 41%）；square 重复 3 次，**Z 三次全 304.0mm 零波动**，后两次一致性 0.3%。
5. **内参补全**：`ros2 topic echo .../camera_info --once` 读到 fx=911.413、fy=909.794、cx=653.027、cy=367.938、D 全 0。
6. **rqt compressed 出图**：选 `/camera/camera/color/image_raw/compressed` 正常出图，清掉 image_transport「装好不会用」的欠账。
7. **排障**：相机掉到 USB 2.0（480M）导致 640×480@15 且一直 Frames timeout → 换 USB 3.0 口（5000M）恢复 720p30。

## 三、踩坑记录（§7 要求，写进档案）

1. **透明茶色亚克力透红外**：深度采到板后墙面（306.5mm）而非板面（295mm），导致 Z 偏大 3.9%；必须背后垫白纸/贴墙。
2. **中文标点打进命令报错**：`.python3` 找不到，命令里只能用 ASCII 符号。
3. **A4 纸不能用 square**：四边平均 (297+210+297+210)/4=253.5mm，报 -14.6% 假误差；square 只适用正方形。
4. **板子太小点角误采背景**：100mm 板四角采到 774mm 背景，必须让板子贴不透明支撑面。
5. **USB 2.0 掉速**：`lsusb -t` 查 480M，换 USB 3.0 蓝口到 5000M 才恢复。
6. **L 型/凸字件点不出方形四角**：只能测重复性、不能报绝对误差，诚实记录优于硬凑百分比。

## 五、需更正的一条错误结论（重要）

- 豆包把「深度读数比机壳量大 10mm」错误归因为「**D435i 深度零点偏移 +10mm、精密测量要补偿 -10mm**」。
- 真相（Intel 数据手册）：D435i 深度值从**前玻璃**起算，前玻璃到左红外传感器中心线约 **4.7mm**；那个 +10mm 是**量距基准面不同**（用亚克力板卡机壳量距 vs 深度从前玻璃起算，差一个机身厚度）造成的，**不是相机固有偏置，不能统一减 10mm**。
